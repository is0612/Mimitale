# UI/UX 审计 + 编辑角色页两版方案（v2）

两件事，一份文档：

- **第一部分**：`client/renderer` 现有界面的 UI/UX 审计（结论 + 证据 + 优先级）。
- **第二部分**：编辑角色页的**两版新方案**——A 稿「长卷」与 B 稿「工坊」。

静态稿，**只读**：不读也不写客户端数据，不参与客户端运行。直接用浏览器打开 `index.html` 即可，无需服务、联网或依赖。

> ⚠️ 和 `design/editor-redesign/`（2026-10-16 已落到客户端的那一版）的关系：
> 那版是**修补**（骨架不变、排版重做）。这两版是**两个不同的方向**，都要在已落地版之上再动：
> B 稿与已落地版同族（都是「两栏 + 分段控件」），差别在右栏多一面镜子；
> A 稿是结构性改动（去掉字段切换这件事本身）。
>
> 提交前请一并看文末的「**已经定过的口径（本次审计照办，不再重提）**」—— 星宝今天否决过「完成度 / 进度条」，
> 两版稿里都没有它。

# 第一部分 · UI/UX 审计

## 证据基础

| 来源 | 说明 |
| --- | --- |
| 项目自带 5 条 CSS lint | `tools/audit-spacing|audit-radius|audit-font|audit-css-dup|audit-css-dead`，本次实跑 |
| 客户端源码 | `renderer/index.html`、`js/views/characterEditorLayout.js`、`js/views/characterEditor.js`、`renderer/style.css`（9309 行） |
| 截图 | `client/tools/shots/charEditorPage.png`（2026-10-16 14:19）、`wbEditorPage.png` |
| 项目既有记录 | 注入量实测 4301 字 / 单角色（2026-09-30）、`maxTokens` 预算与「状态表写进 reasoning」两个已排查过的失败模式 |

## 先说做得好的（这部分别动）

1. **样式纪律是真的有东西守着的。** 5 条 lint 全绿：`line-height` **0 处**、奇数边距 **0 处**、写死盒状圆角 **0 处**（37 处形状类：圆形/胶囊）、写死字号 **0 处**（9 处 em、3 处刻意保留的容器占位字）、**死类名 0 个**（610 个类名）。手写 9000 行 CSS 能做到这个程度，靠的是脚本而不是自觉——这是本项目最值钱的一条工程习惯。
2. **危险动作是合规的。** 「删除角色」走确认弹窗，**指名对象**并说明后果（「用到它的会话会变回通用助手」），且写盘失败会把角色和会话解绑一起**回滚**（`characterEditor.js:1119-1195`）。
3. **键盘是通的。** `wireTabs()` 给两层 tab 都做了方向键 / Home / End + roving `tabindex`（`characterEditorLayout.js:22-36`），`:focus-visible` 焦点环有定义。
4. **提示语诚实。** 上传入口写清了用途（「用在消息气泡和状态卡上」），没写「点击上传图片」这种废话。
5. **状态有交代。** 无角色可编时给 `char-empty`；保存状态胶囊在输入时翻成「有未保存的改动」。

## 问题清单（按严重度）

### P1 · 写作时看不到全貌

**证据**：`characterEditorLayout.js` 的 `selectField()` 用 `hidden` 让五个写作字段**一次只留一个**；出图 `char-01…char-05` 每张只有**一片**写作纸。

**后果**：这五个字段是互相依赖的——描述里的人设决定性格怎么写、场景怎么开、开场白怎么收。一次只看一个，就得反复切换、无法比对、改完第三段忘了第一段写的什么。**这不是排版问题，是工作方式问题。**

### P2 · 层级噪音：三层横条压在一格编辑区上

**证据**：从顶到内容依次是「页头（面包屑+标题+保存）」→「分区标题 + 说明」→「分段控件」→（分隔）→ 写作纸。而**分区导航和分段控件在视觉上同构**（都是一排可选项）——改版说明里自己也写过「两层 tab 分不清层级」。

**后果**：真正该抢眼的写作面被压到第 4 层；1440×960 的第一屏只有**一格**编辑区。

### P3 · 「写」和「后果」之间没有桥

**证据**：编辑器只写不演。写了 5 个字段 + 属性 + 表情，但**看不到**它们会被怎么拼进提示词、占多少预算、在聊天里长什么样。而本项目已知的两个失败模式**都发生在注入层**：注入量实测 4301 字/局；`maxTokens: 2048` 时思考先吃光预算，正文和状态表都挤不出来。

**后果**：调卡变成盲调——改完只能靠「再聊一轮看看」。编辑器对这一层完全沉默。

### P4 · 左栏很紧，右栏很空

**证据**：改版说明记录「说明行在窗口 ≤900px 高时要收起，否则左栏会被截」——说明左栏余量已经很紧。同时 1440×960 里 300px 写作纸**下方是整片空白**（测试卡只写了 11 字时尤其明显）。

**后果**：立绘 / 名字 / 标签 / 5 项导航在 244px 里互相挤，而最值钱的竖向空间在浪费。

### P5 · 长文本的格式约定只靠文字教，没有校验

**证据**：`示例对话` 要求「每行以 `{{user}}:` 或 `{{char}}:` 开头、用 `<START>` 分隔」；`开场白` 有「定场 → 登场 → 话头」骨架；描述有 `((动机→障碍→代价→奖励))` 公式。三处**全部**只存在于 `field-help` 的纯文字里，没有任何格式校验或可视化骨架。

**后果**：格式写错不会有人告诉你，要等下一轮跑起来才发现模型没照做。

### P6 · 「跳到某个字段」是隐式需求，但界面里没有入口

**证据**：`showCharacterField()` 专门为「从别处把某个字段亮出来并聚焦」而存在（`characterEditor.js:1002`、`1219` 都在调它）——说明这是真实需求；但用户自己**没有**等价入口可点。

## 已经定过的口径（本次审计照办，不再重提）

1. **不做「完成度 / 进度条」**。星宝 2026-10-16 明确否决：「我加的那档『写了几个字段 + 进度条』整块删掉了」。
   所以本次审计**不把「这张卡写好了没没有信号」列为问题**，两版稿里也**没有**任何完成度、进度、勾选态。
   （每条后面那个数字是**该段字数**，与已落地的分区计数徽章同源，不是「写完了没」的判断。）
2. **头像 / 形象不通栏**：通栏条会从左右两列同时收走高度。两版稿的立绘都在左栏。
3. **行高由星宝自己加**，本次不动 `line-height`（两版稿全文无 `line-height` 声明）。
4. **主题色后面还会改**，所以两版稿里不碰任何配色协调问题（例如「夜间焦点环是金色、主色是苔绿」）。

## 本次审计的局限（如实说明）

- **截图库有过期图**：`chars.png`（10-13）、`chat.png`、`worldbooks.png` 是旧版（侧栏还挂着已删除的「帮助 / 数据」）。本报告的界面证据以 `charEditorPage.png`、`wbEditorPage.png` 和源码为准，未使用这三张。
- **没跑真窗口走查**：键盘全流程、200% 缩放、文字间距覆盖、缺图兜底未实测。lint 与静态结构是客观证据，交互结论来自代码阅读 + 截图。
- **不报对比度结论**：本项目有专门的「算配色对比度必过三关」踩坑记录（主题是否真的存在 / 按 CSS 覆盖链取实际值 / token 用在哪个属性）。没按那三步算过就不下判断。

# 第二部分 · 编辑角色页两版方案

## 路线决策（先定，再画）

| 项 | 取值 | 依据 |
| --- | --- | --- |
| 分支 | **product**（交互界面） | 交付物是可用可评审的编辑界面，不是海报或标识 |
| 模式 | **Devtool / AI workspace** | 面板式工作台、频繁回访、内容密集、技术型用户 |
| 主视觉谱系 | **沿用现有「酒馆式工具感」** | 中性灰底 + 单一琥珀强调 + 4px 圆角 + 密集排布，已定稿，不该被这两版推翻 |
| 辅助谱系 | **文档编辑器 / 写作工具**（只借「文本是主角、编辑器要暴露后果」这一条） | 解决 P1 与 P3；**不借它的皮肤**（不加装饰渐变、不加 hero 大字） |
| 中文 / 双语 | `zh-CN` 单语 | 客户端现状 |
| 目标视口 | 1440×960 常用、1180 最小、390 手机 | 与 `editor-redesign` 同一套 |

**五条不可让的视觉/系统原则**

1. 中性结构 + 单一琥珀强调；语义色只用于语义（危险 / 成功），不做装饰。
2. 边距只留偶数 px、**不写 line-height**、圆角只用 4px 家族、字号只在既定档位上——**沿用项目三条 lint**。
3. 一个区域只有一个滚动属主；任何一栏都不许长出栏内滚动条。
4. 层级靠位置 / 间距 / 字重表达，容器边界取最小值：能用留白就别加卡片。
5. 文本占的面积必须大于界面装饰的面积。

**五条交互原则**

1. 写作字段之间可自由跳转且**不丢上下文**。
2. 保存状态、字数、校验结果必须在**动作点**可见。
3. 高风险动作就近说明对象与后果（沿用现有确认弹窗）。
4. 键盘可达：Tab 顺序合理、Esc 返回、焦点环可见。
5. 窄屏改的是**分组与可达性**，不是把桌面版等比压小。

**共用系统契约（两稿一致）**

- 令牌：`--bg / --bg-side / --bg-elev / --bg-card / --bg-input / --border* / --text / --text-dim / --text-faint / --accent* / --danger* / --ok-text / --radius / --radius-sm / --fs-xs…xl / --focus-ring`，取值**与 `client/renderer/style.css` 完全一致**（`tokens.css`，白天 = `[data-accent='amber']`，夜间 = `[data-theme='dark']`）。
- 字号只用 `--fs-xs(12) / --fs-sm(14) / --fs-md(16) / --fs-lg(18) / --fs-xl(22)`。
- 圆角只用 `--radius(4) / --radius-sm(3)`，胶囊 999px，圆形 50%。
- 图标：沿用客户端那套 24×24 描边 1.7 内联 SVG，**一个表面只用一套**。
- 不加阴影（除 `--shadow-sm` 用于分段控件选中态这种「必须区分层」的地方）；不加渐变。
- 动效：无。只保留 `prefers-reduced-motion` 兜底。

## A 稿「长卷」—— 一张卡就是一份文档

**一句话主张**：把「一次一格」这件事**整个拿掉**。五个写作字段按写作顺序一屏铺开，页面上的导航只剩**一种**：左栏的大纲。

### 版式骨架

```
页头（面包屑 · 全文 373 字 · 保存状态 · 返回 · 保存角色）
├── 左栏 244px（固定，不滚动）
│     形象 + 头像 ｜ 来源胶囊 ｜ 角色名 ｜ 标签
│     ─────────────
│     卡片大纲（唯一的导航）
│       卡片正文：基本描述 174 / 性格 62 / 场景 41 / 开场白 96 / 示例对话 0
│       其他部分：属性 9 / 表情图 3 / 自带世界书 1 / 高级设置 0
└── 右列（唯一的滚动属主）
      写作纸 × 5（描述领起段最大，其余跟着内容走）
      开场白已折成一行 ← 演示折叠态
      示例对话空态
      ── 分节线「以上是卡片正文 · 以下是这张卡的其他部分」──
      属性 / 表情图 / 自带世界书 / 高级设置（折叠到一行摘要）
页脚（导出 · 删除角色）
```

### 关键机制

1. **字段不再互斥**。五个段落在同一个滚动流里，描述 → 性格 → 场景 → 开场白 → 示例对话，就是写卡的自然顺序。
2. **框高跟着内容走**（`field-sizing: content` + `min-height: 72px`；不支持时退回固定高度）。长卷里这一点很关键：写两行就占两行，别让空框把纸撑到看不见下一段。
   > 这是**刻意与已落地版相反**的取舍。已落地版让五个框统一 300px，理由是「同一种东西，高低不一反而让人以为性格可以随便写写」。长卷里这个理由不成立——判断「是不是同一种东西」由同一套纸头和同样的字段名完成，不靠等高；而**省下来的高度直接换成了同屏可见的段数**。
3. **折叠是长卷活下去的前提**。写好的段可以折成一行摘要，大纲上留个实心点。长卷不折叠会滚到失控，所以折叠不是装饰。
4. **导航只有一种**。左栏大纲按「卡片正文 / 其他部分」分组，每条后面跟该段的**字数**；点一条滚到那一段（`scroll-margin-top` + 手动 `scrollTop`，不用平滑动画）。两层 tab 变成零层 tab（P2 的直接解）。
   > ⚠️ 大纲**不带完成度/进度** —— 星宝已否决过，见上面「已经定过的口径」。所以大纲上既不排序也已写好的段、也不给实心/空心点，只有「在哪一段」和「这段多少字」两件事。

### 取舍与风险（说清楚）

- **总高变长**：五段全展开约 1900px+。缓解手段是折叠 + 大纲跳转。如果使用者从不用折叠，A 稿会比现在难受。
- **一次要读完的更多**：对「只想改一个字」的场景，A 稿需要先滚到那一段（大纲一跳解决，但仍是两下）。
- **`field-sizing` 是渐进增强**：不支持时表现为「框高固定 72px 起，内容多了框内滚动」，版式不塌。

### Do / Don't

- ✅ 五个段落一屏可见，写作顺序 = 阅读顺序。
- ✅ 只用一套纸头（图标 + 字段名 + 类型 + 字数 + 折叠）。
- ✅ 「其他部分」用一条分节线明确切出去。
- ❌ 不要给每一段再套一层卡片/阴影。
- ❌ 不要把大纲也做成展开式树（两级就够，别再叠第三层）。
- ❌ 不要在长卷里塞一个「粘性大工具栏」——那等于把 P2 的噪音又请回来。

## B 稿「工坊」—— 编辑面右边加一面镜子

**一句话主张**：中间照旧「一格一改」（**保写作行宽**），但右边**实时显示这张卡运行起来的样子**——每轮注入多少字、状态面板长什么样、登场那一刻长什么样。

### 版式骨架

```
页头（面包屑 · 保存状态 · 返回 · 保存角色）
├── 左栏 244px（固定）   形象 + 头像 ｜ 来源 ｜ 角色名 ｜ 标签 ｜ 分区导航（5 区 · 图标+名称+计数）
├── 中栏（滚动属主）     一条工具栏：角色设定 ｜[基本描述|性格|场景|开场白|示例对话]｜ 共 373 字
│                       一格写作纸（300px）
│                       提示：右栏是这张卡的运行预览：改一个字段，它跟着变。
└── 右栏 300px「运行预览」（滚动属主·可收起）
      ① 每轮会注入 1 812 字 + 预算条（建议上限 2 500 字）
         角色描述 174 / 开场白 96 / 性格 62 / 场景 41 / 属性 9 项 38 / 世界书命中 2 条 80
         通用扮演规则（固定）1 321  ← 灰显，标出「这块不归你管」
      ② 状态面板：分组胶囊 + 字段行，所见即所得
      ③ 登场预览：头像 + 消息头（角色名 / 模型牌 / 时间）+ 开场白 —— **按「去气泡」后的真实消息体渲染**，不是气泡
      脚注：这是按当前草稿算出来的预估，游玩时以实际注入为准。
页脚（导出 · 删除角色）
```

### 关键机制

1. **把注入层暴露出来**（P3 的直接解）。右栏第①块就是「这张卡每轮会吃什么」的清单——哪一块胖、哪一块是 0，一眼看到。这正是本项目已知失败模式发生的那一层。
2. **预算条给一条明确口径**：建议上限 2 500 字，超了变 `--danger`。**必须在稿子和实现里都写清「这是建议值、不是硬限制」**，否则会变成一条假的约束。
   > ⚠️ 这条不是被否决的那个「进度条」。被否决的是**完成度**（写了几个字段、还差什么）——那是主观的「你写完了没」；这条量的是**真实资源**：每轮注入多少字，超了模型真的会丢前面的设定（本项目实测单角色一局 4301 字）。**判据是「它有没有真实后果」**，不是「它长得像不像进度条」。如果哪天把这条改成按「字段填了几个」来算，它就变回被否决的那件事了。
3. **工具栏并成一条**（P2 的直接解）：分区名 + 分段控件 + 字数挤在**同一行**，比已落地版少一条横条。
4. **写作行宽优先**：右栏是可收起的（收起后中栏吃掉全部宽度）；窗口 ≤1080px 时右栏**直接收掉**而不是压窄中栏 —— 宁可没有镜子，也不让正文行宽掉到不适读。
5. **镜子是预估不是实时数据**：脚注必须留着。第③块用的是「当前草稿的开场白」，不是真实聊天记录。
6. **登场预览必须照抄消息区的现状**：客户端 2026-10-12 已把消息区**去气泡**（头像 36px 方形圆角、消息头一条 flex 行、正文 `pre-wrap`，没有气泡底、没有圆头像）。预览里如果再画一个圆角气泡，就是在稿子里复活一个已经被删掉的设计。

### 取舍与风险

- **多一栏 = 多一份注意力成本**。默认展开，但「收起」必须一直是显式可点的（不是靠猜）。
- **预览要真算，就得真跑一遍装配**：落地时需要把 `buildApiMessages` 的装配过程抽成「可预演」的形式，或至少在视图层做一次同口径的估算。**如果实现里只能做粗略估算，脚注口径就要跟着改**，不能反过来把估算说成精确值。
- **右侧数字会让人焦虑**：把「字数」做成显眼的红黄绿，会诱导用户为凑数字而删内容。所以预算条只在**超额**时才染色，正常区间不做任何颜色暗示。

### Do / Don't

- ✅ 每一块预览都标出数据来源（草稿 / 固定规则 / 预估）。
- ✅ 「通用扮演规则」这类用户改不动的块要灰显，别混进可优化的清单里。
- ✅ 镜子收起后，中栏必须立刻吃到释放的宽度。
- ❌ 不要把镜子做成「第三个 tab」——它一旦需要切换才能看，就不再是镜子。
- ❌ 不要给预览区加自己的编辑能力（那会长出第二套写入路径和落盘时机）。
- ❌ 不要在正常区间用颜色暗示「数字不好看」。

## 怎么落地（两稿分别要动什么）

**共同前提**：**所有控件 ID 与监听器都不动**，只挪容器 —— 和当初把编辑器从弹窗改成页面时的做法一样。

| | A 稿 | B 稿 |
| --- | --- | --- |
| `renderer/index.html` | 去掉 `#char-writing-tabs` 分段控件；五个 `char-sheet` 从「互斥面板」改成同层顺序排列；补 `.outline` 与分节线 | 保留 `#char-writing-tabs`；分区标题与分段控件并进同一条 `.work-bar`；新增右栏 `#char-mirror` |
| `views/characterEditorLayout.js` | `selectField()` 从「设 hidden」改成「滚动到锚点 + 更新大纲当前项」；新增 `setCharOutlineState()` | 分区导航不变；`setCharSectionCount()` 照旧喂计数 |
| `views/characterEditor.js` | 接线大纲点击、折叠态持久化（折/展是按卡存的视图状态，不进角色卡数据） | 接线镜子：装配清单、状态面板预览、登场预览三块各自刷新（输入 debounce） |
| 新数据需求 | 无 | **装配预演**：需把 `data/messages.js` 的装配抽成可预演形式，或做同口径估算；**预算常量**：需要一个「建议上限」的单一来源 |
| 样式 | 新增 ~180 行，就地替换原规则 | 新增 ~220 行，就地替换原规则 |

**两稿都不动**：`tools/audit-*.js` 四条 lint 的判据、`data/` 的数据结构、导入导出契约、危险动作确认流程。

3. `a-02` 与 `a-01` 出图**逐字节相同** → 大纲锚点没生效：`.doc` 上的 `scroll-behavior: smooth` 把程序化滚动变成了动画（200ms 内没滚到位），且锚点映射漏了 `a-` 前缀。
4. B 稿的「登场预览」原来画成了气泡 —— 但客户端 2026-10-12 已把消息区**去气泡**（头像 36px 方形圆角、消息头一条 flex 行、正文 `pre-wrap`）。改成照抄现状，否则等于在稿子里复活一个已被删掉的设计。

**没做的检查**（如实列出）：键盘全流程走查、200% 缩放、文字间距覆盖、真窗口 200% 下的 `field-sizing` 回退表现、屏幕阅读器。

## 落地时要注意的几处

1. **`tokens.css` 是抄来的**：客户端改主题色时这份稿子要跟着同步（`editor-redesign/README.md` 里已经提过同一条），否则预览会骗人。
2. **A 稿的折叠态是视图状态，不是角色卡数据**：折/展不该写进 `characters`，否则会污染导入导出契约。按卡记住即可（类似现在的 `returnView` 那种会话内状态）。
3. **B 稿的镜子会碰到装配层**：`buildApiMessages` 现在是「装配 + 发送」一体的，要预演就得先把它拆开。这是 B 稿唯一的**结构性改造**，工作量比看起来大。
4. **两条 lint 要守住**：新写样式里不出现 `line-height`、`padding/margin/gap` 只用偶数 px。稿子已按这套写（`shell.css` / `variant-*.css` 均无 `line-height`）。
5. **B 稿的右栏在 ≤1080px 直接收掉**，不是压窄 —— 这条别在实现时为了「保住预览」而放松。
