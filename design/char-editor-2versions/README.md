## 一、检查结论（摘要）

完整报告：`.workbuddy/UI-UX检查-角色编辑页-2026-10-16.md`。**视觉底子是好的**（token 齐、字号零违规、两套 tab 的层级上一轮已分清、对比度全达标），问题全在"写作这件事"本身：

| # | 问题 | 证据 |

## 二、两版各自的主张

**V1 精修版** —— 骨架完全不动（左栏 244 + 右列），只把右列内部改成「稿纸 + 旁注」。顶部胶囊仍在，一次仍是一个字段。**HTML 只动一处**：把写作字段框底的说明/模板从 `.char-sheet` 的 footer 挪到旁注列。

**V2 重组版** —— 字段切换这件事被去掉：五个字段连成一张长稿，右栏变成字段目录（带字数与已写标记，滚动时高亮当前栏）。代价是这一页必然要滚动（总高约 1290px），换来的是**写性格时看得见描述**。

## 三、V1 规格

### 3-1 尺寸表（全部为真实 px，可直接抄）

| 部位 | 值 | 依据 |
| --- | --- | --- |
| 左侧主导航 | 196px 固定 | 与客户端一致 |
| 角色资料栏 | **244px 固定**（沿用现状） | `style.css:8077` 同一值 |
| 页头高 | 78px | 与上一版稿一致 |
| 内容区内边距 | 上 24 / 左右 32 / 下 28 | |
| 稿纸宽 | **672px** | 672 − 36(padding 18×2) = **636px 正文宽 → 16px 字号下 40 字/行**（舒适区上限 45） |
| 旁注列宽 | **224px**，间距 24px | 672+24+224 = 920；右列可用 968，**余 16px 给滚动条**（10px）与呼吸位 |
| 面板头 / 字段胶囊 | `max-width: 920px` | 让「AI 辅助」的右缘与旁注列右缘对齐，不飘在空白里 |
| 稿纸高度 | 描述 340 / 性格 200 / 场景 180 / 开场白 260 / 示例 240 | 按各字段的**典型长度**给，不再一律 300：场景天然一两句，描述天然要写三段 |

**没写进表但要守住的两条**：稿纸与旁注一律 `align-items: start`；旁注整列 `position: sticky; top: 0`（内容长时不跟着漂走）。

### 3-2 状态矩阵

| 元素 | 常态 | 悬停 | 选中 | 禁用 |
| --- | --- | --- | --- | --- |
| 分区导航项 | 文字 `--text-dim` | 底色 `--accent-wash` | 底色 `--accent-soft-strong` + 字重 600 | 未定义（现状也没有，见待定 §5-5） |
| 字段胶囊 | `--text-dim`，数字 `--text-faint` | 文字 `--text` | 卡片底 + 字重 600 + 数字走 `--accent` | 同上 |
| 空字段的胶囊 | 数字降透明度 0.7 | — | — | — |
| 保存态胶囊 | `saved`：灰点 + `--text-faint` | — | — | — |
| | `dirty`：`--accent` 点 + 文字 | — | — | — |
| | `saving`：`--text-dim` + 呼吸动画（1.1s） | — | — | — |
| 保存按钮 | 主色实心 | `--accent-hover` | 按下 `--accent-pressed` | **无改动时禁用**：`--bg-input` 底 + `--text-faint` 字 |
| 稿纸 | 1px `--border` | — | 聚焦 `--accent-border`（`:focus-within`） | — |

### 3-3 徽章口径（这条是这次最该统一的）

**全列只允许一种含义：该分区里"已存在的条目数"。** 只有"字段"有自然总数，所以只有它用分数：

| 分区 | 徽章 | 读法 |
| --- | --- | --- |
| 角色设定 | `4/5` | 已写 4 栏 / 共 5 栏 |
| 属性 | `9` | 已定义 9 项 |
| 表情图 | `3` | 已设 3 张 |
| 世界书 | `1` | 已绑 1 本 |
| 高级设置 | `0` | 三栏都还空着（**0 要显示出来**，不能隐藏——隐藏会让人以为是"没有这个功能"） |

### 3-4 落地映射（改哪些文件）

| 改动 | 文件 | 要点 |
| --- | --- | --- |
| 右列改「稿纸 + 旁注」两列 | `renderer/style.css`（`#view-char-editor .char-editor-content` 一带） | 就地改原规则，**不要留末尾覆盖层**（否则 `audit-css-dup` 立刻报同选择器重复） |

## 四、V2 规格

### 4-1 尺寸表

| 部位 | 值 | 依据 |
| --- | --- | --- |
| 角色资料栏 | **220px**（比 V1 窄 24） | 三栏总宽要先算得下 |
| 稿纸 | **650px** | 三栏合计 220+650+280 = 1150；可用 1244，余 94px 给两处内边距与滚动条 |
| 正文宽 | 650 − 36 = **614px ≈ 38 字/行** | 与 V1 同一舒适区间 |
| 字段目录列 | **280px**，左边框 1px `--border`，底色 `--bg-side` | 与左栏同色 → 左右夹住中间的稿纸 |
| 中栏内边距 | 上 20 / 左右 18 / 下 32 | 让稿纸宽度与栏宽严丝合缝，不留"半截空白" |
| 稿纸高度 | 描述 264 / 性格 120 / 场景 100 / 开场白 160 / 示例 140 | 五栏同屏，高度要整体收一档（描述那栏实测内容需 228px，取 264 留 36px 余量） |
| 栏间距 | 16px | 比 V1 的 24 紧：五栏连排时行距太大就切断了"同一张卡"的连续性 |
| 折叠条高 | 36px（`details`，默认收起） | 五栏同屏时，五段说明全部铺开会淹掉正文 |

**V2 的滚动是设计的一部分**：五栏总高约 1290px，中栏视口 822px —— 必须滚。所以这一版**不给"一屏看全"的承诺**，卖点是"描述与性格能同屏对照"（第 1 栏 340px + 第 2 栏 196px + 栏间距 16，一屏放得下）。

### 4-2 新增的唯一逻辑

字段目录要高亮"当前在看的哪一栏"。用 `IntersectionObserver` 观察五张 `.sheet`，取最靠上的可见项设为 `aria-current="true"`，约 20 行。**注意坑**：中栏是滚动容器，observer 的 `root` 要显式传中栏元素 —— 留默认的 `root: null`（视口）现在也能跑，但等哪天中栏变成嵌套滚动就会整片失灵。

### 4-3 状态矩阵

与 V1 一致，只多两处：

| 元素 | 常态 | 选中 |
| --- | --- | --- |
| 字段目录项 | 文字 `--text-dim`，字数 `--text-faint`，状态点 `--border-hover` | 底色 `--accent-soft-strong` + 字重 600 |
| 目录项里的状态点 | 未写 = `--border-hover`；**已写 = `--accent`** | — |
| 空字段的稿纸 | 边框改**虚线**（`is-empty`） | — |

### 4-4 落地映射

| 改动 | 文件 | 要点 |
| --- | --- | --- |
| 去掉字段胶囊 | `characterEditorLayout.js:99-129` | 不再创建 `.char-writing-tabs`；五个 `.field` 直接留在同一个 panel 里 |
| 三栏网格 | `style.css:8077` | `grid-template-columns: 244px minmax(0,1fr)` → `220px minmax(0,1fr) 280px` |
| 新增右栏 | `characterEditorLayout.js` + `index.html` | 需要新建一个 `aside.char-field-index` 并挂在 `#char-form` 下（`form.append(identity, main, index)`） |
| 滚动联动 | 新增约 20 行 | 见 §4-2 |
| 五栏的说明改折叠 | `style.css` + `index.html` | `.char-sheet` 的 footer 换成 `<details class="char-fold">` |
| 备选开场白 | `index.html`（`#c-alt-field`） | 现在跟着「开场白」panel 走，V2 下要挪进同一张稿纸的折叠区 |

## 五、待你拍板（这几条我没有替你决定）

1. **选哪一版** —— 或者第三种：**V1 打底 + 把 V2 的字段目录搬过来**（三栏，但保留顶部胶囊）。我个人推荐先落 V1（改动面最小、能当天验完），再单独评估字段目录。
2. **保存按钮"无改动即禁用"要不要** —— 界面上更清楚，但挡住了"我想手动再存一次"这种习惯。
3. **行宽取多少** —— 现在 40 字/行（672px）。想更沉浸可收到 34 字/行（约 560px），想更紧凑可放到 46 字/行（760px）。这条纯口味，数字我给到区间。
4. **左栏的「导出 / 删除角色」**是否收进左栏底部（现在在底部通栏）。收进去的好处是删除离保存更远；不改也行。
5. **禁用态要不要补全** —— 现在两版都还没设计"世界书没绑定时，绑定相关的操作长什么样"；缺态是上线后最常见的返工点，建议单独排一轮。

## 六、已知取舍（不谎报）

- **出图用的是静态稿，不是真机渲染**。字体是系统字体（`Microsoft YaHei UI`），与 Electron 里一致；但**滚动条、focus ring 这类系统绘制细节，以真机为准**。
- 稿纸高度是按典型长度定的**建议值，不是实测最优值** —— 真实数据下来之后要按 p95 长度再调一轮。
- 两版都**没有动**：角色卡的字段含义、数据契约、导入导出、世界书绑定逻辑。这些不在本次范围内。
- **没有碰** `client/` 任何代码，也没有碰 `design/editor-v2/`、`design/char-editor-v2/`（另一条线的目录）。
- 素材（品牌标、头像、森林图）都是项目自有，无外部 IP 风险；文中出现的"锈钉酒馆"是项目自己的世界设定。
