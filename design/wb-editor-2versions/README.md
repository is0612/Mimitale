# 编辑世界书页 · 两版方案

上一轮只出了**编辑角色页**（`design/char-editor-2versions/` 选版 → `design/editor-v2/` 审计 + A/B），
编辑世界书页漏了。这份补上：**同一套做法、同一条纪律** —— 先量现状、再出两版、逐屏自检。

怎么看：

```bash
# 并排对比（推荐先看这个）
start design/wb-editor-2versions/compare.html
# 交互版（点分区标签切换、点条目行切选中态）
start design/wb-editor-2versions/index.html
```

交互版的地址栏路由：`#a/entries` · `#a/book` · `#a/chars` · `#b/entries` · `#b/book` · `#b/chars`。

## 一、现状：先量，再改

在真客户端上量的（1440×900，用一本 51 条条目的真实世界书）。**这四条是这份稿子要解决的靶子**：

| 项 | 现状实测 | 为什么是问题 |
| --- | --- | --- |
| 顶栏三件套吃掉的高度 | 页头 78 + 书籍头 100 + 分区标签 47 = **225px** | 900 的窗口里，**四分之一**还没看到一个字段。而且页头（「世界书 / 阿多利翁」）、书籍头（书名 + 「51 条设定 51 启用 0 常驻 0 角色」）、书籍设置右栏的「本书信息」（条目 / 常驻 / 角色 / 总字数 / 最后修改）**三处统计重复** |
| 条目列表宽度 | **280px**（行内 253px） | 51 条里有 **19 条**的别名行被截断（`圣盾城 / Aegis City / Aegis / Holy C…`），占 37% |
| 条目行高 | **88px** | 三行（标题 / 别名 / 元信息）各占一行，一屏只看得到 7 条 |
| 正文列宽 | **840px ≈ 60 字/行** | 舒适阅读区是 30–45 字/行。60 字意味着眼睛扫一行要横跨半个屏 |
| 元信息被压 | 「51 字 · 顺序 100」显示成 **「51 字 · 1」** | 绝对定位的 × 删除按钮压在元信息上，100 的最后两位被盖住 |
| 分区语义 | 「常驻条目 / 递归 / **应用这条条目**」三颗，前两颗是 checkbox，第三颗是**填色主按钮形态** | 三颗都是「这条怎么生效」的状态，却长成两种样子；填色那颗看着像动作按钮 |

> 一个反直觉的发现：**窄窗（1180）下现状反而「正常」** —— 正文列被压到 580px ≈ 41 字/行，
> 正好落在舒适区。也就是说 1440 下那 840px 是**没被利用的空间**，不是设计取舍。

## 二、两版的方向（差在一处根本判断）

**A 稿「条目工作台」——编辑单元是「一条条目」**

一天里九成时间在写条目，所以给条目一台**三栏工具**：左列表、中正文、右本条属性；书本身很少改，
于是它退成一条 64px 的信息条，书籍设置 / 本书角色是两个结构完全不同的二级页。

**B 稿「书籍工作台」——编辑单元是「这本书」**

一条条目、一项设置、一个角色，本质是同一本书的三个面。所以**三屏共用一副骨架**：
书级主控头（96px，封面 + 书名 + 统计 + 动作常驻）+ 左目录（分区 + 当前分区清单）贯穿三屏；
右边只换内容。条目的属性不再占一栏，收成正文上方一条**横向属性条**。

| | A 稿 条目工作台 | B 稿 书籍工作台 |
| --- | --- | --- |
| 顶栏吃掉 | **158px** | **146px** |
| 条目屏结构 | 列表 336 \| 正文 640 \| 属性 248（三栏） | 目录 304 \| 正文（属性在上方横条） |
| 书籍信息在哪 | 一条 64px 的书名条；统计只在「书籍设置」出现一次 | 96px 主控头，统计以 chip 行常驻 |
| 分区怎么切 | 顶部标签（条目 51 / 书籍设置 / 本书角色） | **左栏目录**，三屏都在同一位置 |
| 删除本书 | 书籍设置右栏的红色卡（不在正文流里） | 主控头上一颗红色按钮 + 设置页里的卡 |
| 正文列 | 640px ≈ **39 字/行** | 680px ≈ **46 字/行** |
| 列表宽度 / 别名截断 | 336px / **1 行**（现状 19） | 304px / **1 行**（现状 19） |
| 条目行高 | **59px**（现状 88） | **59px** |
| 窄屏（<1280） | 属性栏**折到底部横排**，正文拿回 42 字/行 | 左目录收窄，正文 41 字/行 |

**两版共同解决的问题**：顶栏砍掉 60–80px、统计去重（全书统计只出现一次，书名不再出现三遍）、
列表放宽、正文收进舒适区、条目行瘦身、元信息不再被 × 压住、三颗状态开关形态统一。

## 三、逐屏说明

### A 稿

- **`a-01-entries` 条目** —— 左 336 列 51 条（每行两行：`名称 + 状态徽章 + 字数·顺序` / `关键词`，
  高 59px，一屏 11 条）；中 640 的正文列，两张稿纸卡：**「这条怎么被认出来」**（条目名称 + 关键词
  并排 —— 这两个是"怎么被命中"，不是正文）+ **「内容」**（带序号 + 字数角标 + 折叠写法说明）；
  右 248 是**本条属性**：三个开关（启用 / 常驻 / 递归，各带一句说明）、顺序 / 概率 / 附加条件、
  以及一条「这段话什么时候会进提示词」的预测句。
  > 右侧栏存在的理由：这三个开关 + 两个数字属于「这一条」，放进正文里会把正文打散；
  > 挪到右栏之后，**改完立刻看见**，不用在长表单里上下找。
- **`a-02-book` 书籍设置** —— 左栏两张稿纸（封面与书名 / 开场白），右栏「本书信息」+ 「删除这本书」。
  删除从「横在左栏下面的红条」改成右栏底部的卡：**位置稳定、不占正文宽度**。
- **`a-03-characters` 本书角色** —— 卡片网格 `minmax(280px, 1fr)`，每张卡：头像 + 名字 + 「本书副本」
  徽章 + 一句话 + 两颗动作。顶部一条动作行，右侧一句「3 个角色 · 副本只属于这本书」。
- **`a-05-narrow` 窄屏** —— `@media (max-width: 1280px)` 用 `grid-template-areas` 把右栏从**右边**折到
  **下面横排**（三张卡并排）。**纯 CSS，不需要 JS 配合**。不折的话 1180 下正文只剩 22 字/行。

### B 稿

- **`b-01-entries` 条目** —— 主控头 96px（封面 48×72 + 书名 + 「51 条条目 / 51 启用 / 12 常驻 / 3 角色 /
  2 506 字」chip 行 + 预览命中 / 导出 / 删除本书）；左 304：分区目录三行（当前项高亮）→ 分隔线 →
  搜索 → 51 条清单；右：**横向属性条**（启用 / 常驻 / 递归 + 顺序 + 概率 + 附加条件，一行放完）+
  两张稿纸。
  > 属性条与稿纸**同宽同轴**（都 680 居中）—— 边缘不对齐会显得「条」是飘着的。
- **`b-02-book` 书籍设置** —— 左栏换成设置锚点（封面与书名 / 开场白 / 高级选项 / 删除这本书），
  右栏三张卡：封面与书名（横排）、开场白（带折叠说明）、删除这本书（危险色卡）。
  书籍头已经把统计显示了，这里**不再重复**。
- **`b-03-characters` 本书角色（空态）** —— 现状是「一行灰字 + 一片空白」。改成一张**虚线引导卡**：
  说明「世界书里的角色只在绑定了这本书的会话里出现，和角色库相互独立」，给主次两颗按钮，
  底下补一句「AI 生成会按这本书已有的 51 条设定起一个草稿」。
  > 两版的角色屏**故意各演示一种状态**：A 稿给「有 3 个角色」的样子，B 稿给「空态」的样子。
  > 两种状态都要看，分开展示比各出一半省图也看得更清。

## 四、验证（`capture.cjs` 自检）

```bash
env -u ELECTRON_RUN_AS_NODE client/node_modules/electron/dist/electron.exe \
  --no-sandbox design/wb-editor-2versions/capture.cjs          # 可加 --only=a / --only=b
```

**11 / 11 通过，控制台报错 0 条。** 每屏都过这 8 项：

| 检查 | 门槛 | 结果 |
| --- | --- | --- |
| 横向溢出 | 不允许 | 11/11 通过 |
| 顶栏吃掉的高度 | ≤ 200px（预算 164；现状 225） | A 158 / B 146 |
| 正文每行汉字数 | ≤ 48（舒适区 30–45；现状 60） | A 39–43 / B 41–46 |
| 条目别名截断 | ≤ 10 行（现状 **19**） | 1440 下 1 行；A 稿窄屏 9 行 |
| 左栏栏内滚动条 | 不允许 | 通过 |
| 图片全部加载 | 必须 | 通过 |
| 控件被挤出视口 | 不允许 | 通过 |
| 每屏可见内容块数 | ≥ 1 | 通过 |

另有一项**像素取色**输出（`{"侧栏_20_400": …}`）：`capturePage()` 有可能拿到合成器还没重绘的
陈旧帧 —— 出图过程中就差点把「白天主题侧栏没跟着变」误判成 bug，取色之后确认侧栏是
`237,239,242`（浅色）而不是 `21,23,21`（深色），**白天主题是好的**。

字号 / 圆角 / 间距也按客户端那三条纪律核过：不写 `line-height`、`padding/margin/gap` 里的 px 一律偶数、
圆角只用 `--radius` / `--radius-sm`（胶囊 999px、圆形 50%）。

## 五、挑完之后要落哪些地方

两版都要动的（口径与量都对齐了，改法不同）：

| 文件 | 改什么 |
| --- | --- |
| `client/renderer/index.html` | `#view-wb-editor` 内的结构：书籍头 / 分区标签 / 三栏或左目录 / 属性栏 / 空态卡 |
| `client/renderer/style.css` | `#view-wb-editor` 整段重写（现状那段的通用部分上一轮已经清过一次） |
| `client/renderer/js/views/worldbookLayout.js` | 书籍头、分区、左栏、属性条的装配（现在这里是 `wb-bookbar` / `wb-tabs` / `wb-workspace`） |
| `client/renderer/js/views/worldbook.js` | 条目行的 DOM（`wb-entry-title` / `wb-entry-keys` / `wb-entry-meta` 三行 → 两行）+ 属性开关 |
| `client/tools/smoke-renderer.js` | 世界书编辑页那几条断言要跟着换（选择器、尺寸契约） |
| `CHANGELOG.md` · `使用说明.md` | 用户看得见的行为变了，按约定必须同步 |

**顺带修一处语义**（两版都做）：把「应用这条条目」从"填色主按钮形态的 checkbox"改成和
「常驻条目 / 递归」**同一种开关形态** —— 它表达的是状态，不是动作；三颗长成两种样子，
会让用户以为第三颗能点出什么事来。

**一处建议保留现状**：分区标签上的数字（「条目 51」「本书角色 3」）。它是有用的信息，
A 稿留在顶部标签、B 稿留在左目录，只是位置换了。

## 六、待定（等你拍板）

1. **三栏还是两栏** —— 这是两版唯一不可调和的取舍。A 稿更好写条目（正文永远在同一位置、
   属性一眼可见），B 稿更好管一本书（书籍头常驻、三屏骨架一致）。
2. **书籍头的封面** —— A 稿用 28×42 的小缩略（省高度），B 稿用 48×72（当主控头）。
3. **B 稿的正文列 680 是不是太宽** —— 46 字/行已经压着舒适区上限；如果嫌宽可以收到 640
   （和 A 稿一致），代价是属性条也跟着变窄。
4. **A 稿窄屏的折叠断点** —— 现在定在 1280。定在 1200 还是 1366，取决于你常用的窗口宽度。
